## 1. Почему на Motorola перестал скроллиться терминал

Разобрано полностью, чинить в репозитории нечего.

**Цепочка:** Termux → `~/.bash_profile` делает `exec zsh` → алиас `hs` из
`~/.zshrc`:

```
alias hs='mosh homeserver -- tmux new -A -s work'
```

то есть Claude Code крутится внутри tmux, tmux — внутри mosh. На телефоне
локально живёт только `mosh-client` (проверено: pid 18146,
`mosh-client 100.102.182.105 60001`); сам tmux-сервер — на homeserver.

**Механизм:** и mosh-client, и tmux постоянно держат альтернативный
экранный буфер (`\e[?1049h`). Termux переводит вертикальный свайп одним
пальцем в прокрутку скроллбека **только на основном буфере**. На
альтернативном он вместо этого шлёт стрелки Up/Down — они долетают до
Claude Code и листают историю моих промптов. Это ровно то, что видно.

**Что изменилось именно сегодня:** tmux поставлен 2026-09-17 в 11:16:42,
тогда же приехали zsh/p10k и алиас `hs`, который вписал tmux внутрь mosh.
Сам mosh старый (бинари от 2026-07-04) — новый элемент именно связка.

**Что проверено и оказалось ни при чём:** `~/.termux/termux.properties`.
Диф правки от 11:12 против бэкапа `termux.properties.bak-20260917-1047`
содержит **только два добавления и ни одного удаления** — блок `extra-keys`
и `allow-external-apps=true`. Ни одного свойства про скролл/мышь там не
появлялось и не пропадало. Восстанавливать нечего.

**Что делать:**

1. Когда цель — читать, а не работать: `hss` (чистый ssh, без mosh и tmux).
   Основной буфер, родной скроллбек Termux возвращается. В истории zsh
   `hss` не использовался ни разу — привычки нет, её стоит завести.
2. Создать `~/.tmux.conf` **на homeserver** (не на телефоне — файла там нет
   и быть не должно, tmux-сервер удалённый):

   ```
   set -g mouse on
   set -g history-limit 50000
   ```

   Тогда свайп в Termux начнёт водить собственный скроллбек tmux.
3. Либо руками: `prefix` + `[` — copy-mode tmux, дальше стрелки/PageUp,
   выход `q`.

Принципиальное ограничение: mosh по устройству не имеет скроллбека вообще.
Единственный доступный в этом стеке скроллбек — это история tmux, поэтому
пункт 2 — настоящее решение, а пункт 1 — обход.

## 2. Пять пунктов усиления против апстрима

Общая дыра: **ничто не проверяет, что после cherry-pick патч всё ещё на
месте.** Разрешённый руками конфликт может выбросить аддитивный кусок
внутри файла, который апстрим и так поставляет, — и результат соберётся.
Так однажды и потерялся патч build-тега в `router_linux.go`.

### Что уже сделано

`docs/vau/android.sh.next` — новый `scripts/android.sh`, в котором закрыты
все пять. Разбор по пунктам:

1. **Манифест дельты.** Новые подкоманды `manifest [--write]` и
   `verify [base]`, файл `scripts/fork-manifest.txt` формата:

   ```
   base v1.102.4
   head c77f750ba
   [files]
   <added>\t<deleted>\t<path>        # все 67 путей
   [markers]
   <path>\t<буквальная строка из нашего хунка>
   [absent]
   <path>\t<строка, которую наш патч удалил>
   ```

   `[files]` ловит патч, потерянный целиком. `[markers]` — главное:
   маркеры ставятся **только для файлов, которые уже существуют в
   апстриме на базе** (`git cat-file -e $base:$f`); новый файл либо
   выживает целиком, либо исчезает из `[files]`, маркер ему не нужен.
   Опасен обратный случай: +76 строк в апстримовский `netstack.go`,
   тихо выброшенные при конфликте, — компилируется. Маркер ставится **на
   каждый хунк** и равен самой длинной добавленной строке, которая
   встречается в пропатченном файле ровно один раз (12..200 символов, без
   табов); уникальность и есть то, что отличает характерную строку от
   болванки. `[absent]` — зеркало для хунков, которые только удаляют:
   у них нет добавленной строки, чтобы её пинать, поэтому пинается
   отсутствие удалённой. `verify_manifest` валит сборку на потере,
   расхождение чисел строк — только информация (апстрим законно
   дрейфует).

2. **Сборка как жёсткий гейт.** В `cmd_build` — отказ, если `VERSION_LONG`
   содержит `-dirty`, с `--allow-dirty` как явным выходом. В `cmd_update`
   бывший советующий блок "Next steps" превращён в исполняемый гейт:
   после cherry-pick сначала манифест, потом реальная сборка
   `--nocgo arm64`; `--no-build` — опт-аут.

3. **`compat --check` заранее.** У `cmd_compat` появился `--rc`: прогон
   по `-pre`/`-rc` тегам. Побочно изменено поведение по умолчанию —
   раньше фильтр был только `grep -v android`, и pre-теги молча попадали
   в обычный прогон; теперь по умолчанию только стабильные, а pre —
   отдельным режимом. **Осталось сделать:** добавить шаг в
   `.github/workflows/upstream-watch.yml`. Сейчас там на строке 55
   `gh release list ... --exclude-pre-releases`; трогать этот путь
   нельзя, нужен отдельный шаг/джоб, который берёт свежайший pre-тег и
   гоняет `scripts/android.sh compat --rc --check`.

4. **`git rerere`.** `git config --get rerere.enabled` был `(unset)`.
   Добавлен `enable_rerere()` (вызывается в `compat` и `update`) и
   `clone_shared()`: `git clone --shared` **не** разделяет
   `.git/rr-cache`, поэтому клон получает симлинк на кэш настоящего репо
   плюс `rerere.enabled/autoupdate`. Без этого разрешённый один раз
   конфликт пришлось бы разрешать заново в каждом временном клоне, а
   конфликтуют там из раза в раз одни и те же build-теги и `go.mod`.

5. **Не схлопывать вилку в один коммит.** `git reset --soft` в трёх
   местах (было: строки 146-147, 256, 298) заменён на настоящий реплей
   диапазона `git cherry-pick "$base_commit..$head_sha"`; `head_sha`
   снимается **до** первого `git checkout`. `--squash` оставлен как
   опт-аут.

   **Честно о пределе этого пункта:** история вилки сейчас вырожденная —
   `git rev-list bbcd7d1fc..HEAD` это ровно два коммита, `632b9af4e`
   (67 файлов, сам по себе не собирается) и `c77f750ba` (2 файла,
   правка после ребейза). Реплей диапазона — правильная смена
   **механизма** и работает для любой длины серии, но настоящей
   погранулярности конфликтов он не даст, пока `632b9af4e` не разрезан на
   тематическую серию. А разрезание переписывает историю, уже
   опубликованную в `origin/android-v1.102.4` на `c77f750ba`, то есть
   требует force-push. **Это решение пользователя, молча не делать.**

### Что пришлось доправить в черновике

Вычитка глазами (шаг 1 списка ниже) нашла шесть дефектов — A–F. Ещё два,
G и H, вылезли только на прогоне (шаги 3 и 6): оба про расхождение между
тем, что скрипт думает про чужой вывод, и тем, что тот выводит на самом
деле, — чтением такое не ловится. Все восемь исправлены на месте, файл
вырос с 643 строк до 719.

- **A. Тихая смерть в `cmd_compat`.** Фильтр тегов
  `all=$(git tag -l ... | grep -v android ...)` при пустом результате
  возвращает 1, а под `set -euo pipefail` (строка 17) голое присваивание из
  подстановки команд убивает скрипт **без единого слова** — проверка
  `if [ -z "$tags" ]` ниже была недостижима. Добавлен `|| true` в трёх
  местах; гейт снова печатает «No tags found».
- **B. `grep -qF` давал ложное «маркер на месте».** Подстрочный поиск
  отвечает на «встречается ли где-нибудь», а маркер обязан утверждать «эта
  строка присутствует целиком». Наши патчи build-тегов тег **укорачивают**,
  поэтому строка вилки — буквальный префикс апстримовской, и `grep -F`
  попадал всегда. Заменено на сравнение строки целиком (с точностью до
  ведущих отступов). Ловило 2 маркера из 59, проходивших на неотпатченном
  апстриме: `//go:build (!linux && !freebsd && !windows && !darwin) `
  (хвостовой пробел там настоящий и несущий) в
  `net/netmon/netmon_polling.go` и `//go:build linux` в
  `ssh/tailssh/incubator_linux.go`.
- **C. Два маркера на файл оставляли хунки без присмотра.** У
  `util/linuxfw/iptables_runner.go` семь хунков и два маркера — пять без
  покрытия, у `ssh/tailssh/incubator.go` 6/2, дальше 4/2, 4/2, 3/2.
  Потерянный хунк оставляет путь в numstat, то есть проходит как «дрейф» и
  сборку не валит. Теперь маркер на каждый хунк: 7/7, 6/6, 4/4, 4/4, 3/3.
- **D. Три файла оставались вообще без маркера.** Виноваты границы длины
  16..120: у `cmd/tailscaled/tailscaled.go` добавленная строка 124 символа
  (это и есть переключение `no-logs-no-support` в `true`), у
  `envknob/featureknob/featureknob.go` — `case "android":`, 15 символов,
  у `feature/taildrop/fileops_fs.go` добавленных строк нет вовсе (см. E).
  Границы раздвинуты до 12..200, а безопасным это делает новое требование
  **уникальности**: кандидат обязан встречаться в пропатченном файле ровно
  один раз. Оно же отсекает неотличимую болванку вроде `if err != nil {`,
  которая прошла бы и на апстриме.
- **E. Удаления не проверялись ничем.** Манифест утверждал только наличие
  добавленных строк. Появилась секция `[absent]`. Ровно такой формы был
  потерянный когда-то патч, и ровно такой единственный случай в нынешней
  дельте — `feature/taildrop/fileops_fs.go`, где снимается
  `//go:build !android` и не добавляется ничего.
- **F. Мелочи.** `trap`-очистка `/tmp/tailscale-compat-$$`,
  `/tmp/fork-manifest-$$.txt`, `/tmp/tailscale-update-$$` (раньше временное
  убиралось только на успешном пути); `--no-renames` у всех
  `git diff --numstat`, чтобы переименование не читалось как «патч потерян
  целиком»; `cmd_update` зовёт себя как `"$0"`, а не по относительному
  `./scripts/android.sh`; `--empty=drop` на трёх реплеях диапазона — если
  апстрим сам принял наш патч, коммит становится пустым и cherry-pick
  сейчас встаёт посреди серии; с `--empty=drop` серия доходит до конца, а
  вердикт выносит манифест («патч потерян целиком»), что и есть правильный
  громкий сигнал.
- **G. Счётчики манифеста врали.** `cmd_manifest` печатал итог тремя
  `awk`-диапазонами, и у диапазона маркеров не было терминатора: он
  открывался на `[markers]` и шёл до конца файла, прихватывая заголовок
  `[absent]` и его строку, — 70 вместо 68. Счётчик удалений при этом не
  печатался вовсе. Незакрытый `awk`-диапазон молча перетекает в следующую
  секцию, и расхождение видно только если пересчитать руками. Терминаторы
  расставлены, вывод стал «69 файлов, 68 маркеров, 1 удалений».
- **H. Гейт `-dirty` был холостым.** Черновик проверял грязь так:
  `printf '%s' "$ldflags" | grep -q -- '-dirty'`. Но версию даёт `mkversion`
  через `./build_dist.sh shellvars`, и она выглядит как `1.102.4-5-tde9187c6a`
  — тег, расстояние, коммит; суффикса `-dirty` там не бывает ни при каких
  условиях. Проверено в лоб: на чистом и на грязном дереве `shellvars`
  выдаёт байт в байт одно и то же, то есть гейт пропускал сборку всегда.
  Судя по комментарию, черновик целился в Go VCS stamping (`vcs.modified`
  в buildinfo) — то есть проверял артефакт подсистемы, которая к строке
  версии отношения не имеет. Теперь гейт смотрит на `git status --porcelain`
  — единственного настоящего свидетеля, — и переехал выше `setup_ndk`,
  чтобы на грязном дереве не качался NDK. Untracked считаются грязью
  осознанно: лишний `.go` в пакете компилируется наравне с остальными,
  а `git describe --dirty` его не видит. Проверено в три стороны: грязное
  дерево → rc=1, подкинутый untracked `.go` → rc=1 и виден в списке,
  `--allow-dirty` → собирается.

Получившийся манифест: 69 файлов, 68 маркеров, 1 запись `[absent]`. Прогон:
68/68 принимаются на нашем дереве, 0/68 проходят на чистом апстриме @base
(до правки B проходило 2); удалённая строка действительно есть на базе и
действительно отсутствует у нас, то есть `[absent]` не вырожденная.
