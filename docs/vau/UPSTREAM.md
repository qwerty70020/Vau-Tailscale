## 1. Почему на Motorola перестал скроллиться терминал

Разобрано полностью, чинить в репозитории нечего.

**Цепочка:** Termux → `~/.bash_profile` делает `exec zsh` → алиас `hs` из
`~/.zshrc`:

```
alias hs='mosh homeserver -- tmux new -A -s work'
```

то есть Claude Code крутится внутри tmux, tmux — внутри mosh. На телефоне
локально живёт только `mosh-client` (проверено: pid 18146,
`mosh-client 100.102.182.105 60001`); сам tmux-сервер — на homeserver.

**Механизм:** и mosh-client, и tmux постоянно держат альтернативный
экранный буфер (`\e[?1049h`). Termux переводит вертикальный свайп одним
пальцем в прокрутку скроллбека **только на основном буфере**. На
альтернативном он вместо этого шлёт стрелки Up/Down — они долетают до
Claude Code и листают историю моих промптов. Это ровно то, что видно.

**Что изменилось именно сегодня:** tmux поставлен 2026-09-17 в 11:16:42,
тогда же приехали zsh/p10k и алиас `hs`, который вписал tmux внутрь mosh.
Сам mosh старый (бинари от 2026-07-04) — новый элемент именно связка.

**Что проверено и оказалось ни при чём:** `~/.termux/termux.properties`.
Диф правки от 11:12 против бэкапа `termux.properties.bak-20260917-1047`
содержит **только два добавления и ни одного удаления** — блок `extra-keys`
и `allow-external-apps=true`. Ни одного свойства про скролл/мышь там не
появлялось и не пропадало. Восстанавливать нечего.

**Что делать:**

1. Когда цель — читать, а не работать: `hss` (чистый ssh, без mosh и tmux).
   Основной буфер, родной скроллбек Termux возвращается. В истории zsh
   `hss` не использовался ни разу — привычки нет, её стоит завести.
2. Создать `~/.tmux.conf` **на homeserver** (не на телефоне — файла там нет
   и быть не должно, tmux-сервер удалённый):

   ```
   set -g mouse on
   set -g history-limit 50000
   ```

   Тогда свайп в Termux начнёт водить собственный скроллбек tmux.
3. Либо руками: `prefix` + `[` — copy-mode tmux, дальше стрелки/PageUp,
   выход `q`.

Принципиальное ограничение: mosh по устройству не имеет скроллбека вообще.
Единственный доступный в этом стеке скроллбек — это история tmux, поэтому
пункт 2 — настоящее решение, а пункт 1 — обход.

## 2. Пять пунктов усиления против апстрима

Общая дыра: **ничто не проверяет, что после cherry-pick патч всё ещё на
месте.** Разрешённый руками конфликт может выбросить аддитивный кусок
внутри файла, который апстрим и так поставляет, — и результат соберётся.
Так однажды и потерялся патч build-тега в `router_linux.go`.

### Что уже сделано

`docs/vau/android.sh.next` — новый `scripts/android.sh`, в котором закрыты
все пять. Разбор по пунктам:

1. **Манифест дельты.** Новые подкоманды `manifest [--write]` и
   `verify [base]`, файл `scripts/fork-manifest.txt` формата:

   ```
   base v1.102.4
   head c77f750ba
   [files]
   <added>\t<deleted>\t<path>        # все 67 путей
   [markers]
   <path>\t<буквальная строка из нашего хунка>
   ```

   `[files]` ловит патч, потерянный целиком. `[markers]` — главное:
   маркеры ставятся **только для файлов, которые уже существуют в
   апстриме на базе** (`git cat-file -e $base:$f`); новый файл либо
   выживает целиком, либо исчезает из `[files]`, маркер ему не нужен.
   Опасен обратный случай: +76 строк в апстримовский `netstack.go`,
   тихо выброшенные при конфликте, — компилируется. Маркер = самая
   длинная добавленная строка (16..120 символов, без табов), она же самая
   характерная. `verify_manifest` валит сборку на потере, расхождение
   чисел строк — только информация (апстрим законно дрейфует).

2. **Сборка как жёсткий гейт.** В `cmd_build` — отказ, если `VERSION_LONG`
   содержит `-dirty`, с `--allow-dirty` как явным выходом. В `cmd_update`
   бывший советующий блок "Next steps" превращён в исполняемый гейт:
   после cherry-pick сначала манифест, потом реальная сборка
   `--nocgo arm64`; `--no-build` — опт-аут.

3. **`compat --check` заранее.** У `cmd_compat` появился `--rc`: прогон
   по `-pre`/`-rc` тегам. Побочно изменено поведение по умолчанию —
   раньше фильтр был только `grep -v android`, и pre-теги молча попадали
   в обычный прогон; теперь по умолчанию только стабильные, а pre —
   отдельным режимом. **Осталось сделать:** добавить шаг в
   `.github/workflows/upstream-watch.yml`. Сейчас там на строке 55
   `gh release list ... --exclude-pre-releases`; трогать этот путь
   нельзя, нужен отдельный шаг/джоб, который берёт свежайший pre-тег и
   гоняет `scripts/android.sh compat --rc --check`.

4. **`git rerere`.** `git config --get rerere.enabled` был `(unset)`.
   Добавлен `enable_rerere()` (вызывается в `compat` и `update`) и
   `clone_shared()`: `git clone --shared` **не** разделяет
   `.git/rr-cache`, поэтому клон получает симлинк на кэш настоящего репо
   плюс `rerere.enabled/autoupdate`. Без этого разрешённый один раз
   конфликт пришлось бы разрешать заново в каждом временном клоне, а
   конфликтуют там из раза в раз одни и те же build-теги и `go.mod`.

5. **Не схлопывать вилку в один коммит.** `git reset --soft` в трёх
   местах (было: строки 146-147, 256, 298) заменён на настоящий реплей
   диапазона `git cherry-pick "$base_commit..$head_sha"`; `head_sha`
   снимается **до** первого `git checkout`. `--squash` оставлен как
   опт-аут.

   **Честно о пределе этого пункта:** история вилки сейчас вырожденная —
   `git rev-list bbcd7d1fc..HEAD` это ровно два коммита, `632b9af4e`
   (67 файлов, сам по себе не собирается) и `c77f750ba` (2 файла,
   правка после ребейза). Реплей диапазона — правильная смена
   **механизма** и работает для любой длины серии, но настоящей
   погранулярности конфликтов он не даст, пока `632b9af4e` не разрезан на
   тематическую серию. А разрезание переписывает историю, уже
   опубликованную в `origin/android-v1.102.4` на `c77f750ba`, то есть
   требует force-push. **Это решение пользователя, молча не делать.**

### Ещё один факт, который надо держать в голове

`.github/workflows/upstream-watch.yml` **уже** делает пункты 2 и 5
правильно: строка 85 — `git cherry-pick "refs/tags/$CUR..origin/$GITHUB_REF_NAME"`,
диапазон, без squash; строки 94-103 — сборка, и шаг с PR на строке 106
требует `steps.build.outcome == 'success'`. Небезопасен был именно
локальный `scripts/android.sh`. Асимметрия CI/локалка — вот что чинится.

### Что осталось руками

1. Прочитать `docs/vau/android.sh.next`, прогнать глазами дифф против
   текущего `scripts/android.sh` (338 строк).
2. `mv docs/vau/android.sh.next scripts/android.sh && chmod +x scripts/android.sh`
3. `./scripts/android.sh manifest --write` — сгенерировать
   `scripts/fork-manifest.txt` из реальных данных git.
4. Закоммитить скрипт + манифест, затем **перегенерировать манифест ещё
   раз**: `scripts/android.sh` и `scripts/fork-manifest.txt` сами входят в
   дельту вилки, их numstat меняется этим же коммитом.
5. `./scripts/android.sh verify` — должно быть чисто.
6. `./scripts/android.sh build --nocgo arm64` — проверить, что гейт
   `-dirty` не ложно срабатывает на чистом дереве.
7. `git config rerere.enabled true && git config rerere.autoupdate true`
   в настоящем репо (скрипт делает это сам при первом `compat`/`update`,
   но лучше явно).
8. Добавить RC-шаг в `upstream-watch.yml` (пункт 3 выше).
9. Спросить пользователя про разрезание `632b9af4e` — это force-push.

Мелочь заодно: в `get_build_tags` ссылка на `VAU-AUDIT.md` устарела,
в черновике уже исправлена на `docs/vau/AUDIT.md`.
